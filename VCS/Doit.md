7. ПОЛЬЗОВАТЕЛЬСКИЕ СТРАНИЦЫ НА DJANGO TEMPLATES
==================================================

Пользовательские страницы должны быть отдельными обычными Django views/templates, а не страницами внутри Django Admin. (вообще в идеале втиснуть в админку Unfold как бесшовный вариант)

Создай:
- общий базовый шаблон с оформлением ЭНГС;
- CSS на основе прототипа;
- две страницы:
  1. `/matrix/`
  2. `/problems/`

При необходимости корневой URL `/` может перенаправлять на `/matrix/`.

Настрой:
- `templates/` в корне проекта;
- `static/css/engs.css`;
- urls приложения `apps.reports`;
- подключение urls в `app/urls.py`.

Используй цветовую схему из прототипа:
- тёмно-синий: `#00234B`;
- бирюзовый: `#00DCC8`;
- красный: `#D21E41`;
- жёлтый: `#E6C800`;
- зелёный для актуальных проверок.

Страницы должны требовать авторизации через `login_required`. (в идеале оставаться в рамках джанго админки!)
Для демонстрации допустимо входить через уже созданную административную учётную запись. Если добавление небольшой стандартной страницы входа через Django `LoginView` не усложняет работу, реализуй её в том же фирменном стиле.

------------------------------
Страница `/matrix/`
------------------------------

Реализуй календарную матрицу:

- строки — активные ТС, для которых `is_subject_to_inspection=True`;
- колонки — дни выбранного периода;
- по умолчанию — текущий месяц;
- пользователь может передать GET-параметры `date_from` и `date_to`;
- ограничь отображаемый диапазон разумным максимумом, например 92 дня;
- в ячейке показывай название утренней геозоны из `VehicleMorningGeozone`;
- если статус `OUTSIDE`, показывай `Вне геозон`;
- если записи нет либо статус `NO_DATA`, показывай `—`;
- если в этот день есть активная проверка, показывай зелёный кружок;
- если у проверки есть файл со ссылкой, клик по индикатору либо ячейке может открывать ссылку в новой вкладке;
- закрепи шапку и первый столбец через CSS, как в прототипе;
- добавь карточки со статистикой: всего ТС, зелёные, жёлтые, красные.

Цвет ячейки должен считаться на backend относительно даты конкретной ячейки:

- если на дату ячейки у ТС ещё не было проверки — красный;
- если последняя проверка на дату ячейки была менее 30 дней назад — зелёный/белый;
- если прошло от 30 до 90 дней включительно — жёлтый;
- если прошло более 90 дней — красный.

Очень важно:
- не используй будущую проверку для окрашивания прошлой даты;
- проверка от 30 дней назад уже должна давать жёлтый статус;
- не рассчитывай бизнес-логику в браузере;
- избегай N+1-запросов к базе: данные за период загружай пакетно и собирай матрицу в Python/service-layer.

Вынеси расчёт матрицы и статусов в `apps.reports.services`, чтобы view оставался простым.

------------------------------
Страница `/problems/`
------------------------------

Реализуй страницу «Проблемные ТС по геозонам»:

- показывай только ТС со статусом жёлтый или красный на текущую дату либо переданную дату анализа;
- для каждого ТС выводи:
  - госномер;
  - статус;
  - дату последней проверки;
  - количество дней без проверки;
  - основную утреннюю геозону;
- группируй ТС по основной утренней геозоне;
- основная геозона определяется как наиболее часто встречающаяся утренняя геозона ТС за выбранный анализируемый период, например последние 90 дней;
- добавь GET-параметр количества дней периода анализа, по умолчанию 90;
- сохрани визуальный стиль карточек геозон и бейджей из HTML-прототипа.

CSV-экспорт сейчас можно не реализовывать, если это увеличивает сроки. Главное — рабочие две страницы и корректная бизнес-логика.
